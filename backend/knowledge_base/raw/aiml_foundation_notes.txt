AI/ML FOUNDATION NOTES

Machine learning projects should start with a clear problem definition, a measurable success metric, and a baseline workflow. In an interview, a strong answer should explain how the candidate would move from raw data to a validated model rather than jumping directly to a complex algorithm.

Core workflow:
- define the business or product objective
- identify the prediction target or decision task
- inspect the dataset for missing values, label quality issues, and class imbalance
- split data into train, validation, and test sets without leakage
- build a simple baseline before using a high-capacity model
- evaluate with task-appropriate metrics
- inspect failure cases and iterate

Good AI/ML engineers explain why validation matters. They should mention that a model can appear strong on training data while failing on real inputs. They should discuss data leakage, overfitting, and mismatched evaluation metrics.

Common validation ideas:
- compare against a baseline model
- track precision, recall, F1, ROC-AUC, regression error, or ranking metrics depending on the task
- review confusion matrices or error slices
- test robustness on edge cases
- examine whether the model behaves consistently across subgroups

In computer vision workflows, useful safeguards include:
- verifying annotation quality
- checking image resolution and preprocessing consistency
- handling class imbalance or rare events
- evaluating under blur, occlusion, and lighting variation
- considering latency and deployment constraints in addition to accuracy

Expected strong interview themes:
- problem framing
- preprocessing discipline
- baseline-first thinking
- validation methodology
- failure analysis
- production tradeoffs
